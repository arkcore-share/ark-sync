## 1. 概述与适用场景

Syncthing 是去中心化的连续文件同步工具，用于在两台或多台设备之间自动同步文件。

典型场景：

- 个人电脑与笔记本双向同步工作目录
- 服务器与办公终端共享资料
- 多组织通过中转设备做隔离同步
- 通过 REST API 做自动化接入与运维

核心特性：

- 端到端加密（TLS）
- 无中心存储，数据仅在设备间传输
- 支持版本保留、冲突处理、忽略规则
- 跨平台（Windows/macOS/Linux/BSD）

## 2. 部署前准备

### 2.1 端口规划

默认端口（可在配置中修改）：

- `8384`：Web GUI / REST API
- `22000/tcp`、`22000/udp`：设备间同步传输
- `21027/udp`：局域网发现

若有防火墙，请放行上述端口或按需放行你自定义的端口。

### 2.2 网络与权限

- 同步目录建议使用本地磁盘路径，避免不稳定网络挂载路径。
- 运行用户需对同步目录有读写权限。
- 容器部署时明确 `UID/GID`，避免宿主机权限错配。

### 2.3 设备命名规范（建议）

建议在添加设备时统一命名：`部门-角色-主机名`，例如 `dev-laptop-01`，便于后续排障与审计。

## 3. 安装方式

你可以按实际环境选择一种方式。

### 3.1 包管理安装（推荐）

#### Ubuntu / Debian

```bash
curl -fsSL https://syncthing.net/release-key.txt | sudo gpg --dearmor -o /usr/share/keyrings/syncthing-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/syncthing-archive-keyring.gpg] https://apt.syncthing.net/ syncthing stable" | sudo tee /etc/apt/sources.list.d/syncthing.list
sudo apt update
sudo apt install -y syncthing
```

#### macOS（Homebrew）

```bash
brew install syncthing
```

#### Windows

到官网下载并安装：<https://syncthing.net/downloads/>

### 3.2 二进制安装

1. 下载与你系统架构匹配的压缩包。
2. 解压后将 `syncthing` 放入 `PATH`（如 `/usr/local/bin`）。
3. 执行 `syncthing --version` 验证。

### 3.3 源码编译（本仓库）

仓库根目录执行：

```bash
go run build.go
```

构建产物位于 `./bin` 目录。

## 4. 首次启动与初始化

### 4.1 启动

```bash
syncthing
```

常用参数：

```bash
syncthing --no-browser      # 启动但不自动打开浏览器
syncthing --version         # 查看版本
syncthing deviceid          # 查看本机设备 ID
```

### 4.2 访问 Web 界面

默认访问地址：`http://127.0.0.1:8384`

首次启动时，Syncthing 会生成配置与证书文件。

常见配置目录：

- Linux：`~/.config/syncthing/`
- macOS：`~/Library/Application Support/Syncthing/`
- Windows：`%LOCALAPPDATA%\Syncthing\`

关键文件：

- `config.xml`：主配置
- `cert.pem` / `key.pem`：TLS 证书与私钥
- `index-*.db`：索引数据库

### 4.3 首次安全设置（强烈建议）

在 GUI 中完成：

1. 设置 GUI 登录用户名和密码。
2. 记录 API Key（自动化调用 REST 使用）。
3. 若需公网访问 GUI，开启 TLS 并限制来源 IP。

## 5. 两台设备快速打通

以设备 A 与设备 B 为例：

1. 在 A 上复制设备 ID（操作 -> 显示 ID）。
2. 在 B 上“添加远程设备”，填写 A 的 ID。
3. 在 A 上接受 B 的设备请求。
4. 在 A 上创建文件夹并共享给 B。
5. 在 B 上接受文件夹共享并选择本地目录。

推荐初始同步模式：

- 普通协作：`发送接收`（双向）
- 主备分发：主端 `仅发送`，从端 `仅接收`

## 6. 日常使用

### 6.1 文件夹管理

创建文件夹时重点关注：

- `Folder ID`：建议全局唯一且可读（如 `finance_docs`）
- `Path`：必须是本机可访问路径
- `Type`：发送接收 / 仅发送 / 仅接收 / 接收加密
- `Rescan Interval`：扫描间隔（秒）

### 6.2 忽略规则 `.stignore`

在文件夹根目录创建 `.stignore`：

```txt
*.log
node_modules/
.tmp/
.DS_Store
Thumbs.db
!important.log
```

### 6.3 冲突文件处理

当多端同时改同一文件可能生成冲突副本。建议：

- 在团队内约定编辑窗口
- 启用版本保留
- 定期清理冲突并合并内容

### 6.4 REST 健康检查

```bash
curl -s http://127.0.0.1:8384/rest/noauth/health
curl -s -H "X-API-Key: <API_KEY>" http://127.0.0.1:8384/rest/system/status
```

## 7. 服务化运行与自启动

### 7.1 Linux systemd（用户级）

```bash
systemctl --user enable syncthing
systemctl --user start syncthing
systemctl --user status syncthing
journalctl --user -u syncthing -f
```

### 7.2 其他系统服务模板

仓库 `etc/` 目录提供多平台示例：

- `etc/linux-systemd/`
- `etc/macos-launchd/`
- `etc/freebsd-rc/`
- `etc/linux-upstart/`

按目标系统选择并调整路径、用户、端口。

## 8. Docker 部署详解

参考仓库 `README-Docker.md`，推荐使用 host 网络模式。

### 8.1 Docker CLI

```bash
docker pull syncthing/syncthing
docker run --network=host \
  -e STGUIADDRESS= \
  -e PUID=1000 \
  -e PGID=1000 \
  -v /wherever/st-sync:/var/syncthing \
  --name syncthing \
  --restart unless-stopped \
  syncthing/syncthing:latest
```

### 8.2 Docker Compose

```yaml
version: "3"
services:
  syncthing:
    image: syncthing/syncthing
    container_name: syncthing
    hostname: my-syncthing
    environment:
      - PUID=1000
      - PGID=1000
      - STGUIADDRESS=
    volumes:
      - /wherever/st-sync:/var/syncthing
    network_mode: host
    restart: unless-stopped
```

### 8.3 容器部署注意事项

- 默认进程 UID/GID 为 `1000:1000`，需与宿主目录权限匹配。
- `network_mode: host` 更有利于局域网发现与直连性能。
- 若将 GUI 暴露到公网，务必启用认证和 TLS。

## 9. 升级、迁移与备份

### 9.1 升级建议

- 先备份配置目录与同步根目录元数据。
- 小规模验证后再全量升级。
- 生产环境尽量固定版本并分批发布。

### 9.2 迁移到新机器

1. 停止旧实例。
2. 复制 `config.xml`、证书文件、必要数据目录到新机器。
3. 确认新机器路径与权限一致。
4. 启动后观察设备连接与文件夹状态。

### 9.3 备份范围

至少备份：

- 配置目录（含 `config.xml`、`cert.pem`、`key.pem`）
- 业务同步数据目录
- （可选）日志与运维脚本

## 10. 故障排查

### 10.1 常见问题与处理

1. GUI 打不开
- 检查进程是否运行：`ps -ef | grep syncthing`
- 检查端口：`ss -lntup | grep 8384`
- 检查防火墙策略

2. 设备一直离线
- 核对双方设备 ID 是否正确
- 检查 `22000/tcp`、`22000/udp` 是否可达
- 尝试临时配置静态地址（替代 `dynamic`）

3. 文件不触发同步
- 检查文件夹是否暂停
- 检查 `.stignore` 是否误匹配
- 手动触发重扫或缩短 `Rescan Interval`

4. Docker 容器有权限错误
- 检查挂载目录 owner/group
- 设置 `PUID/PGID` 与宿主机用户一致

### 10.2 日志定位

- GUI：查看“日志”面板
- systemd：`journalctl --user -u syncthing -f`
- 容器：`docker logs -f syncthing`

## 11. 安全加固建议

- GUI 必须启用用户名/密码。
- REST 调用使用 API Key，仅保存在服务端。
- 仅在必要网段开放 8384 管理端口。
- 使用 HTTPS 或反向代理 TLS 终止。
- 定期轮换 API Key，并审计自动化调用来源。
- 对跨组织共享按文件夹隔离，最小权限授权。
