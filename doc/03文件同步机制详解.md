### 同步核心流程

```
1. 文件变更检测 (Scanner)
   ↓
2. 更新本地数据库 (SQLite DB)
   ↓
3. 发送索引更新到对端 (Index Handler)
   ↓
4. 对端接收索引并计算差异 (Model)
   ↓
5. 请求文件数据块 (Puller)
   ↓
6. 接收并写入文件 (Puller)
   ↓
7. 更新本地数据库 (SQLite DB)
   ↓
8. 同步完成 ✓
```

## 核心概念

### 1. 文件信息 (FileInfo)

每个文件在 Syncthing 中用一个 `FileInfo` 结构表示：

```go
type FileInfo struct {
    Name           string        // 文件路径
    Size           int64         // 文件大小（字节）
    ModifiedS      int64         // 修改时间（Unix 时间戳）
    ModifiedBy     ShortID       // 最后修改的设备 ID
    Sequence       int64         // 序列号（单调递增）
    Version        Vector        // 版本向量
    Blocks         []BlockInfo   // 数据块哈希列表
    LocalFlags     FlagLocal     // 本地标志
    NoPermissions  bool          // 是否忽略权限
}
```

### 2. 版本向量 (Version Vector)

用于追踪哪个设备最后修改了文件：

```
版本向量示例:
Device A: 10, Device B: 5

含义:
- A 修改了 10 次
- B 修改了 5 次
- 最新版本是 A 的修改
```

### 3. 序列号 (Sequence Number)

- 每个文件夹维护一个单调递增的序列号
- 每次文件变更都会分配新的序列号
- 用于增量索引交换（只发送序列号更高的文件）

### 4. 数据块 (Blocks)

文件被分成固定大小的块（默认 128KB）：

```
文件: example.txt (1MB)
├─ Block 0: 0-128KB,    Hash: sha256(abc...)
├─ Block 1: 128-256KB,  Hash: sha256(def...)
├─ Block 2: 256-384KB,  Hash: sha256(ghi...)
├─ ...
└─ Block 7: 896KB-1MB,  Hash: sha256(jkl...)
```

## 文件变更检测机制

### 两种检测方式

#### 方式 1: 文件系统监控 (FS Watcher) - 实时

**工作原理**:
```go
// lib/model/folder.go

// 启动文件系统监控
func (f *folder) startWatch(ctx context.Context) {
    f.watchChan = make(chan []string)
    
    // 使用 OS 的原生监控机制
    // Linux: inotify
    // macOS: FSEvents  
    // Windows: ReadDirectoryChangesW
    watcher := newWatcher(f.Filesystem, f.watchChan)
    
    go func() {
        for events := range watcher.C {
            // 收到文件变更事件
            f.watchChan <- events.Paths
        }
    }()
}
```

**流程**:
```
用户修改文件 "document.txt"
    ↓
操作系统发出 inotify 事件
    ↓
Syncthing 收到事件
    ↓
触发扫描 (Scan)
    ↓
计算文件哈希
    ↓
更新数据库
```

#### 方式 2: 定期扫描 (Periodic Scan) - 兜底

**工作原理**:
```go
// lib/model/folder.go

// 定时扫描（默认 3600 秒 = 1 小时）
scanInterval := time.Duration(cfg.RescanIntervalS) * time.Second
f.scanTimer = time.NewTimer(scanInterval)

go func() {
    for {
        select {
        case <-f.scanTimer.C:
            // 执行完整扫描
            f.scan(ctx)
        }
    }
}()
```

### 扫描过程 (Scanner Walk)

**代码位置**: `lib/scanner/walk.go`

```go
func (w *walker) walk(ctx context.Context) chan ScanResult {
    toHashChan := make(chan protocol.FileInfo)
    finishedChan := make(chan ScanResult)
    
    // 1. 遍历文件系统
    go w.scan(ctx, toHashChan, finishedChan)
    
    // 2. 并行计算哈希
    newParallelHasher(ctx, w.Folder, w.Filesystem, 
                      w.Hashers, finishedChan, toHashChan)
    
    return finishedChan
}
```

**扫描步骤**:

```
步骤 1: 遍历目录树
├─ 读取文件元数据 (大小、修改时间、权限)
├─ 检查 .stignore 忽略规则
└─ 对比数据库中的旧 FileInfo

步骤 2: 检测变更
├─ 文件大小变化 → 需要重新哈希
├─ 修改时间变化 → 需要重新哈希
├─ 权限变化 (如果不忽略权限) → 仅更新元数据
└─ 文件名/路径变化 → 新文件 + 删除旧文件

步骤 3: 计算哈希 (如果需要)
├─ 将文件分成 128KB 的块
├─ 对每个块计算 SHA-256 哈希
├─ 生成 Blocks 列表
└─ 创建新的 FileInfo

步骤 4: 更新数据库
├─ 分配新的序列号 (Sequence++)
├─ 更新版本向量 (Version++)
└─ 写入 SQLite 数据库
```

## 索引交换机制

### Index Handler 工作原理

**代码位置**: `lib/model/indexhandler.go`

#### A 电脑发送索引到 B 电脑

```go
func (s *indexHandler) Serve(ctx context.Context) error {
    // 1. 首次连接：发送完整索引
    err = s.sendIndexTo(ctx)
    
    // 2. 订阅本地索引更新事件
    sub := s.evLogger.Subscribe(events.LocalIndexUpdated)
    
    for {
        // 3. 等待本地文件变更
        select {
        case <-sub.C():  // 本地索引更新了
        case <-ticker.C: // 每分钟检查一次
        }
        
        // 4. 发送增量索引更新
        err = s.sendIndexTo(ctx)
    }
}
```

#### 发送索引更新 (sendIndexTo)

```go
func (s *indexHandler) sendIndexTo(ctx context.Context) error {
    // 1. 从数据库获取序列号大于 prevSequence 的文件
    seq, _ := s.sdb.GetDeviceSequence(s.folder, protocol.LocalDeviceID)
    
    files = s.sdb.GetFilesSequenced(
        s.folder, 
        protocol.LocalDeviceID,
        s.localPrevSequence,  // 从上次的序列号开始
        batchSize             // 批量发送
    )
    
    // 2. 发送 Index 或 IndexUpdate 消息
    if initial {
        // 首次：发送完整索引
        s.conn.Index(ctx, &protocol.Index{
            Folder: s.folder,
            Files: files,
        })
    } else {
        // 后续：发送增量更新
        s.conn.IndexUpdate(ctx, &protocol.IndexUpdate{
            Folder: s.folder,
            Files: files,
            PrevSequence: s.sentPrevSequence,
        })
    }
    
    // 3. 更新已发送的最高序列号
    s.sentPrevSequence = files[len(files)-1].Sequence
}
```

### BEP 协议消息类型

**代码位置**: `lib/protocol/protocol.go`

```
主要消息类型:
├─ Index              // 完整索引（首次连接）
├─ IndexUpdate        // 增量索引更新
├─ Request            // 请求文件数据块
├─ Response           // 响应文件数据块
├─ ClusterConfig      // 集群配置（协商能力）
└─ DownloadProgress   // 下载进度更新
```

### 增量索引交换流程

```
A 电脑                              B 电脑
  │                                   │
  │──── ClusterConfig ───────────────▶│  (协商能力)
  │◀─── ClusterConfig ────────────────│
  │                                   │
  │──── Index (完整索引) ────────────▶│  (首次)
  │     Files: [f1, f2, f3, ...]     │
  │                                   │
  │◀─── Index (完整索引) ─────────────│  (B 也发送)
  │     Files: [f4, f5, f6, ...]     │
  │                                   │
  │  [用户修改了 file.txt]            │
  │                                   │
  │──── IndexUpdate ─────────────────▶│  (增量更新)
  │     Files: [file.txt (v2)]       │
  │     PrevSequence: 100            │
  │                                   │
  │                                   │ [计算差异]
  │                                   │ [发现需要 file.txt]
  │                                   │
  │◀─── Request (Block 0) ────────────│
  │──── Response (Block 0 数据) ─────▶│
  │◀─── Request (Block 1) ────────────│
  │──── Response (Block 1 数据) ─────▶│
  │                                   │
  │                                   │ [组装文件]
  │                                   │ [写入磁盘]
  │                                   │
```

## 文件拉取机制

### Puller 工作流程

**代码位置**: `lib/model/folder_sendrecv.go`

#### 主拉取循环

```go
func (f *sendReceiveFolder) pull(ctx context.Context) (bool, error) {
    changed := 0
    
    // 多次迭代直到没有更多变更
    for tries := range maxPullerIterations {
        // 1. 执行一次拉取迭代
        changed, err = f.pullerIteration(ctx, scanChan)
        
        if changed == 0 {
            break  // 没有更多变更，退出
        }
    }
    
    return changed == 0, nil
}
```

#### 拉取迭代过程

```go
func (f *sendReceiveFolder) pullerIteration(ctx context.Context) (int, error) {
    // 1. 获取需要同步的文件列表
    needFiles := f.model.NeedFolderFiles(f.folderID)
    
    // 2. 创建并发管道
    copyChan := make(chan copyBlocksState)      // 复制块
    pullChan := make(chan pullBlockState)       // 拉取块
    finisherChan := make(chan *sharedPullerState) // 完成处理
    
    // 3. 启动并发 worker
    go f.copierRoutine(ctx, copyChan, pullChan)           // 复制本地块
    go f.pullerRoutine(ctx, pullChan, finisherChan)       // 从远程拉取
    go f.finisherRoutine(ctx, finisherChan, dbUpdateChan) // 完成文件
    
    // 4. 处理每个需要同步的文件
    for _, file := range needFiles {
        f.handleFile(file, copyChan)
    }
    
    return changed, nil
}
```

### 文件拉取详细步骤

```
步骤 1: 确定需要的文件
├─ 查询数据库：SELECT * FROM files WHERE need = true
├─ 比较本地和全局版本向量
└─ 生成需要拉取的文件列表

步骤 2: 创建临时文件
├─ 文件名: .syncthing.filename.tmp
├─ 设置稀疏文件 (Sparse File)
└─ 预留磁盘空间

步骤 3: 获取数据块
├─ 对于每个 Block:
│  ├─ 检查本地是否有 (复用其他文件夹的块)
│  ├─ 从远程设备请求
│  │  ├─ 选择最空闲的设备
│  │  ├─ 发送 Request 消息
│  │  ├─ 接收 Response 消息
│  │  └─ 验证 SHA-256 哈希
│  └─ 写入临时文件 (LimitedWriteAt)
│
└─ 并发执行 (默认 Copiers=4)

步骤 4: 完成文件
├─ 重命名临时文件 → 正式文件
├─ 设置权限和修改时间
├─ 更新数据库索引
└─ 触发版本控制 (如果启用)

步骤 5: 清理
├─ 删除旧版本 (如果启用版本控制)
├─ 记录同步事件
└─ 发送完成事件到 GUI
```

### 并发拉取架构

```
┌──────────────────────────────────────────────────────┐
│                   Puller 管道架构                     │
└──────────────────────────────────────────────────────┘

handleFile()
    │
    ▼
┌──────────────┐
│  copyChan    │ ──▶ copierRoutine (N 个并发)
│  (复制本地块) │      ├─ 从本地查找相同块
│              │      ├─ 复用其他文件夹的块
│              │      └─ 减少网络传输
└──────────────┘
    │
    ▼
┌──────────────┐
│  pullChan    │ ──▶ pullerRoutine (N 个并发)
│  (拉取远程块) │      ├─ 从多个设备并行请求
│              │      ├─ 验证块哈希
│              │      └─ 写入临时文件
└──────────────┘
    │
    ▼
┌──────────────┐
│finisherChan  │ ──▶ finisherRoutine (串行)
│  (完成处理)   │      ├─ 重命名文件
│              │      ├─ 设置元数据
│              │ └─ 更新数据库
└──────────────┘
```

## 增删改同步示例

### 场景 1: 新增文件

```
A 电脑操作:
└─ 创建文件: new_photo.jpg (5MB)

同步流程:

A 电脑:
1. Scanner 检测到新文件
   ├─ 文件: new_photo.jpg
   ├─ 大小: 5,242,880 字节
   └─ 修改时间: 2024-01-15 10:30:00

2. 计算哈希 (分成 41 个块)
   ├─ Block 0: 0-128KB,    Hash: sha256(a1b2c3...)
   ├─ Block 1: 128-256KB,  Hash: sha256(d4e5f6...)
   ├─ ...
   └─ Block 40: 5MB-5MB,   Hash: sha256(x7y8z9...)

3. 更新数据库
   ├─ FileInfo {
   │     Name: "new_photo.jpg",
   │     Size: 5242880,
   │     Sequence: 101,
   │     Version: {A:1},
   │     Blocks: [41 blocks]
   │   }
   └─ 标记为 Global (全局最新)

4. 发送 IndexUpdate 到 B
   └─ Files: [new_photo.jpg]

B 电脑:
1. 接收索引更新
   ├─ 存入数据库
   └─ 发现本地没有此文件 → Need

2. 拉取文件
   ├─ 创建临时文件: .syncthing.new_photo.jpg.tmp
   ├─ 请求 41 个数据块 (并发)
   ├─ 验证每个块的哈希
   └─ 组装成完整文件

3. 完成同步
   ├─ 重命名为 new_photo.jpg
   ├─ 设置权限和修改时间
   └─ 更新数据库

结果: B 电脑也有了 new_photo.jpg ✓
```

### 场景 2: 修改文件

```
A 电脑操作:
└─ 修改文件: document.txt (从 10KB 改为 15KB)

同步流程:

A 电脑:
1. Scanner 检测到修改
   ├─ 文件大小变化: 10KB → 15KB
   └─ 修改时间变化

2. 重新计算哈希
   旧版本:
   ├─ Block 0: Hash(abc...)
   └─ Block 1: Hash(def...)
   
   新版本:
   ├─ Block 0: Hash(abc...)  ← 相同！可以复用
   ├─ Block 1: Hash(xyz...)  ← 不同
   └─ Block 2: Hash(uvw...)  ← 新增

3. 更新数据库
   ├─ 旧 FileInfo 标记为过时
   ├─ 新 FileInfo:
   │   {
   │     Name: "document.txt",
   │     Size: 15360,
   │     Sequence: 102,
   │     Version: {A:12,B:5},  ← A 的版本号增加
   │     Blocks: [3 blocks]
   │   }
   └─ 全局状态更新

4. 发送 IndexUpdate 到 B
   └─ Files: [document.txt (v12)]

B 电脑:
1. 接收索引更新
   ├─ 比较版本向量
   │   本地: {A:11,B:5}
   │   远程: {A:12,B:5}  ← A 更新
   └─ 标记为 Need

2. 拉取文件 (增量)
   ├─ 创建临时文件
   ├─ 检查本地已有块
   │   └─ Block 0 已存在 → 复用 (节省带宽!)
   ├─ 只请求新块
   │   ├─ Request Block 1
   │   └─ Request Block 2
   └─ 组装文件

3. 完成同步
   ├─ 替换旧文件
   ├─ 如果启用版本控制:
   │   └─ 旧版本移动到 .stversions/document.txt~20240115
   └─ 更新数据库

结果: B 电脑的 document.txt 更新为最新版本 ✓
     节省了 33% 的带宽 (复用了 1/3 的块)
```

### 场景 3: 删除文件

```
A 电脑操作:
└─ 删除文件: old_backup.zip

同步流程:

A 电脑:
1. Scanner 检测到删除
   ├─ 文件消失
   └─ 可能是误删，需要记录

2. 更新数据库
   ├─ FileInfo 更新:
   │   {
   │     Name: "old_backup.zip",
   │     Deleted: true,           ← 标记为删除
   │     Sequence: 103,
   │     Version: {A:13,B:5},
   │     Blocks: []               ← 清空块列表
   │   }
   └─ 全局状态更新

3. 发送 IndexUpdate 到 B
   └─ Files: [old_backup.zip (deleted=true)]

B 电脑:
```

## 关键技术实现

### 1. 版本向量冲突检测

```go
// 版本向量比较
func (v Vector) Compare(other Vector) ComparisonResult {
    // 示例:
    // A: {DeviceA: 10, DeviceB: 5}
    // B: {DeviceA: 9,  DeviceB: 6}
    
    // A 有更高的 DeviceA 版本
    // B 有更高的 DeviceB 版本
    // → 冲突！两个设备都修改了文件
    
    if allEqual {
        return Equal        // 相同版本
    }
    if allGreater {
        return Greater      // 当前更新
    }
    if allLess {
        return Lesser       // 远程更新
    }
    return Concurrent       // 冲突！
}
```

```go
// lib/model/folder_sendrecv.go

func (f *sendReceiveFolder) reuseBlocks() {
    // 检查其他文件夹是否有相同的块
    for _, block := range file.Blocks {

        if available := f.model.BlockAvailability(block); available {

    }
    
    // 只请求未复用的块
    blocksToPull = file.Blocks - reused
}
```

## 性能优化策略

### 1. 增量索引交换

```
首次连接:
├─ 发送完整索引 (可能几 MB)
└─ 耗时: 数秒

后续更新:
├─ 只发送变更的文件索引
├─ 数据量: 通常几 KB
└─ 耗时: 毫秒级
```

### 2. 块级去重

```
文件修改:
├─ 只重新计算变化的块
├─ 复用未变化的块
└─ 节省计算和带宽

示例:
10MB 文件，修改了 1MB
├─ 旧方法: 重新传输 10MB
└─ Syncthing: 只传输 1MB (节省 90%)
```

### 3. 并发拉取

```
单文件多块并发:
├─ 从多个设备同时请求不同块
├─ 默认并发数: 4-8
└─ 充分利用带宽

多文件并发:
├─ 同时处理多个文件
├─ 受 I/O 限制器控制
└─ 避免系统过载
```

### 4. 压缩传输

```go
// 索引消息使用 LZ4 压缩
func (c *rawConnection) sendIndex(msg proto.Message) {
    data, _ := proto.Marshal(msg)
    
    if len(data) > compressionThreshold {
        // 大于 128 字节才压缩
        compressed := lz4.Compress(data)
        c.send(compressed)
    } else {
        c.send(data)
    }
}
```

### 5. 批量处理

```go
// 批量发送索引，减少网络往返
type FileInfoBatch struct {
    files []FileInfo
    size  int
    limit int  // 默认 1000 个文件或 8MB
}

func (b *FileInfoBatch) Add(file FileInfo) {
    b.files = append(b.files, file)
    b.size += file.Size
    
    if b.size >= b.limit {
        b.Flush()  // 批量发送
    }
}
```

## 冲突处理机制

### 冲突检测

```
场景: A 和 B 同时修改了同一个文件

A 电脑: {A:10, B:5}  ← A 修改到版本 10
B 电脑: {A:9,  B:6}  ← B 修改到版本 6

比较结果: Concurrent (并发修改)
→ 冲突！
```

### 冲突解决策略

#### 策略 1: 自动解决 (大多数情况)

```go
// 基于版本向量和修改时间
func resolveConflict(local, remote FileInfo) FileInfo {
    // 1. 比较版本向量
    cmp := local.Version.Compare(remote.Version)
    
    if cmp == Greater {
        return local   // 本地更新
    }
    if cmp == Lesser {
        return remote  // 远程更新
    }
    
    // 2. 版本相同，比较修改时间
    if local.Modified > remote.Modified {
        return local
    }
    return remote
}
```

#### 策略 2: 冲突文件 (无法自动解决)

```
当无法确定哪个版本更新时:

A 电脑:
├─ 保留自己的版本: document.txt
└─ 保存远程版本: document.sync-conflict-20240115-103000.txt

B 电脑:
├─ 保留自己的版本: document.txt
└─ 保存远程版本: document.sync-conflict-20240115-103000.txt

用户可以手动检查冲突文件并决定保留哪个版本
```

### 冲突处理示例

```
时间线:
10:00 - A 和 B 都有 document.txt (v1)
10:05 - A 修改了 document.txt (v2-A)
10:05 - B 也修改了 document.txt (v2-B)
10:06 - 同步发生，检测到冲突

结果:
A 电脑:
├─ document.txt                    (A 的版本)
└─ document.sync-conflict-20240115.txt  (B 的版本)

B 电脑:
├─ document.txt                    (B 的版本)
└─ document.sync-conflict-20240115.txt  (A 的版本)

用户操作:
1. 打开两个版本对比
2. 选择保留一个，或手动合并
3. 删除不需要的冲突文件
```

## 总结

### 同步流程关键步骤

```
1. 检测变更 (Scanner)
   ├─ 文件系统监控 (实时)
   └─ 定期扫描 (兜底)

2. 计算哈希 (Hasher)
   ├─ 分块 (128KB)
   └─ SHA-256

3. 更新数据库 (SQLite)
   ├─ 序列号++
   └─ 版本向量++

4. 发送索引 (Index Handler)
   ├─ 首次: 完整索引
   └─ 后续: 增量更新

5. 接收索引 (Model)
   ├─ 比较版本向量
   └─ 计算差异

6. 拉取文件 (Puller)
   ├─ 复用本地块
   ├─ 请求远程块
   └─ 验证哈希

7. 写入磁盘 (Finisher)
   ├─ 临时文件 → 正式文件
   ├─ 版本控制
   └─ 更新数据库

8. 完成同步 ✓
```

✅ **增量同步** - 只传输变化的数据块  
✅ **块级去重** - 跨文件夹复用相同块

✅ **版本向量** - 精确追踪变更历史  
✅ **冲突处理** - 自动解决 + 手动干预  
✅ **压缩传输** - LZ4 压缩索引数据
