## 方案概述

### 什么是中转设备？

中转设备（Bridge Device）是一个 **24 小时在线的 Syncthing 节点**，作为 A 和 B 之间的同步桥梁。

```
传统 P2P 同步:
A ←→ B
需要同时在线

中转设备同步:
A ←→ C ←→ B
A 和 B 不需要同时在线
```

### 为什么需要中转设备？

| 场景 | 问题 | 中转设备解决 |
|------|------|-------------|
| 办公室电脑 + 家里电脑 | 很少同时在线 | ✅ NAS 中转 |
| 跨国团队 | 时差大，重叠时间少 | ✅ 云服务器中转 |
| 移动设备 | 网络不稳定 | ✅ 固定节点中转 |
| 重要数据备份 | 需要高可靠性 | ✅ 专用中转服务器 |

### 中转设备 vs 中继服务器

```
中转设备 C:
├─ 存储完整文件数据
├─ 持久化数据库
├─ 异步同步（A 和 B 不需要同时在线）
├─ 需要自己部署
└─ 速度取决于 C 的性能

中继服务器:
├─ 不存储文件数据
├─ 实时转发
├─ A 和 B 必须同时在线
├─ 社区提供（免费）
└─ 解决网络不通问题
```

## 核心原理

### 1. 多设备共享机制

Syncthing 原生支持**一个文件夹共享给多个设备**：

```xml
<!-- config.xml 中的文件夹配置 -->
<folder id="default" path="/path/to/folder">
  <!-- 共享给设备 A -->
  <device id="DEVICE_A_ID"></device>
  
  <!-- 共享给设备 B -->
  <device id="DEVICE_B_ID"></device>
  
  <!-- 共享给设备 C（中转） -->
  <device id="DEVICE_C_ID"></device>
</folder>
```

**代码实现** (`lib/config/folderconfiguration.go`):
```go
type FolderConfiguration struct {
    ID      string                      `json:"id" xml:"id,attr"`
    Path    string                      `json:"path" xml:"path,attr"`
    Devices []FolderDeviceConfiguration `json:"devices" xml:"device"`
    // ...
}

type FolderDeviceConfiguration struct {
    DeviceID     protocol.DeviceID `json:"deviceID" xml:"id,attr"`
    IntroducedBy protocol.DeviceID `json:"introducedBy" xml:"introducedBy,attr"`
    // ...
}
```

### 2. 索引交换机制

每个设备维护自己的数据库，通过 **ClusterConfig** 交换索引信息：

```
设备 C（中转）的数据库:
├─ local_files: C 自己的文件
├─ remote_files:
│  ├─ from_A: A 的文件索引
│  └─ from_B: B 的文件索引
└─ global_files: 所有设备的最新状态

当 A 上线:
├─ A 发送索引给 C
├─ C 比较差异
└─ C 从 A 拉取更新

当 B 上线:
├─ B 发送索引给 C
├─ C 比较差异
└─ B 从 C 拉取 A 的更新
```

### 3. 版本向量保证一致性

```
场景: A 修改文件，C 同步，B 最后同步

T1: A 修改 document.txt
    版本向量: {A:1}

T2: C 从 A 同步
    版本向量: {A:1}
    C 的数据库记录来源

T3: B 从 C 同步
    版本向量: {A:1}
    B 获得最新版本

关键: 版本向量追踪修改历史
     保证最终一致性
```

## 架构拓扑

### 方案 1: 星型拓扑（推荐）

```
        C (中转设备)
       /    |    \
      /     |     \
     A      B      D
     
特点:
├─ C 是中心节点，24 小时在线
├─ A、B、D 通过 C 同步
├─ A 和 B 不需要直接连接
├─ 配置简单，易于管理
└─ 适合家庭/小团队

同步流程:
A 修改 → C 同步 → B 同步
         ↑
      中转存储
```

### 方案 2: 网状拓扑

```
    A ←→ B
    ↓     ↓
    C ←→ D
    
特点:
├─ 多个中转设备
├─ 冗余备份
├─ 更高的可靠性
└─ 配置复杂

适用场景:
└─ 重要数据，需要高可用
```

### 方案 3: 层级拓扑

```
        C1 (主中转)
       /  \
      /    \
    A       B
    ↓       ↓
   C2      C3
  (备份)   (备份)
  
特点:
├─ 主中转 + 备份中转
├─ 自动故障切换
└─ 企业级部署
```

## 详细部署方案

### 方案 1: 家庭 NAS 中转

#### 硬件要求

```
设备: 群晖/威联通 NAS 或 Raspberry Pi
存储: 根据数据量决定（建议至少 1TB）
网络: 千兆以太网
电源: 7x24 小时运行
功耗: NAS ~30W，树莓派 ~5W
```

#### 部署步骤（以群晖为例）

**步骤 1: 安装 Syncthing**
```bash
# 群晖 DSM 套件中心
# 1. 打开"套件中心"
# 2. 搜索 "Syncthing"
# 3. 点击"安装"

# 或使用 Docker
docker run -d \
  --name syncthing \
  --hostname syncthing \
  -p 8384:8384 \
  -p 22000:22000/tcp \
  -p 22000:22000/udp \
  -p 21027:21027/udp \
  -v /volume1/syncthing:/var/syncthing \
  -e PUID=1000 \
  -e PGID=1000 \
  --restart unless-stopped \
  syncthing/syncthing:latest
```

**步骤 2: 配置中转设备 C**
```
1. 访问 http://NAS_IP:8384
2. 首次设置向导
3. 记录设备 ID（重要！）
4. 设置管理员密码
```

**步骤 3: 添加设备 A 和 B**
```
在设备 C 上:
1. 点击"添加远程设备"
2. 输入设备 A 的 ID
3. 勾选"自动接受文件夹"（可选）
4. 保存

重复添加设备 B
```

**步骤 4: 配置文件夹共享**
```
在设备 C 上:
1. 创建文件夹 "sync_folder"
2. 路径: /volume1/data/sync
3. 共享给设备 A 和 B
4. 设置文件夹类型: "发送接收"
```

#### 完整配置示例（config.xml）

```xml
<configuration version="52">
  <!-- 文件夹配置 -->
  <folder id="default" label="工作文件" 
          path="/volume1/data/work" 
          type="sendreceive">
    <device id="AAAAA-BBBBB-CCCCC-DDDDD-EEEEE-FFFFF-GGGGG-HHHHH"/> <!-- A -->
    <device id="11111-22222-33333-44444-55555-66666-77777-88888"/> <!-- B -->
    <device id="99999-AAAAA-BBBBB-CCCCC-DDDDD-EEEEE-FFFFF-GGGGG"/> <!-- C (自己) -->
    
    <!-- 文件监控 -->
    <fsWatcherEnabled>true</fsWatcherEnabled>
    <fsWatcherDelayS>10</fsWatcherDelayS>
    
    <!-- 定期扫描 -->
    <rescanIntervalS>3600</rescanIntervalS>
    
    <!-- 版本控制（保留删除的文件） -->
    <versioning type="staggered">
      <param key="maxAge" val="31536000"/> <!-- 1年 -->
    </versioning>
    
    <!-- 忽略权限 -->
    <ignorePerms>false</ignorePerms>
    
    <!-- 自动规范化 -->
    <autoNormalize>true</autoNormalize>
  </folder>
  
  <!-- 设备 A 配置 -->
  <device id="AAAAA-BBBBB-CCCCC-DDDDD-EEEEE-FFFFF-GGGGG-HHHHH" 
          name="办公室电脑" 
          compression="metadata">
    <address>dynamic</address> <!-- 自动发现 -->
    <autoAcceptFolders>true</autoAcceptFolders> <!-- 自动接受新文件夹 -->
  </device>
  
  <!-- 设备 B 配置 -->
  <device id="11111-22222-33333-44444-55555-66666-77777-88888" 
          name="家里电脑" 
          compression="metadata">
    <address>dynamic</address>
    <autoAcceptFolders>true</autoAcceptFolders>
  </device>
  
  <!-- 全局选项 -->
  <options>
    <!-- 监听地址 -->
    <listenAddress>
      <string>default</string>
    </listenAddress>
    
    <!-- 启用全局发现 -->
    <globalAnnounceEnabled>true</globalAnnounceEnabled>
    
    <!-- 启用本地发现 -->
    <localAnnounceEnabled>true</localAnnounceEnabled>
    
    <!-- 启用中继 -->
    <relaysEnabled>true</relaysEnabled>
    
    <!-- 速率限制（0 = 无限制） -->
    <maxSendKbps>0</maxSendKbps>
    <maxRecvKbps>0</maxRecvKbps>
  </options>
</configuration>
```

```
├─ 存储: 100GB SSD（根据需求调整）

月费用: ~50-100 元
```

**步骤 2: 安装 Syncthing**
```bash
# SSH 登录服务器
ssh root@YOUR_SERVER_IP

apt update
apt install syncthing

# 创建服务
systemctl enable syncthing@root
systemctl start syncthing@root
```

**步骤 3: 配置防火墙**
```bash
# 开放必要端口
ufw allow 22000/tcp  # TCP 同步
ufw allow 22000/udp  # QUIC 同步
ufw allow 21027/udp  # 本地发现
ufw allow 8384/tcp   # Web GUI（可选，建议限制 IP）

# 如果只允许特定 IP 访问 GUI
ufw allow from YOUR_OFFICE_IP to any port 8384
```

**步骤 4: 配置 Nginx 反向代理（可选）**
```nginx
# /etc/nginx/sites-available/syncthing
server {
    listen 80;
    server_name syncthing.example.com;
    
    location / {
        proxy_pass http://127.0.0.1:8384;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# 启用 HTTPS（Let's Encrypt）
certbot --nginx -d syncthing.example.com
```

**步骤 5: 优化配置**
```xml

<options>
```

## 工作原理详解

### 1. ClusterConfig 交换机制

**代码位置**: `lib/model/model.go`

```go
func (m *model) ClusterConfig(conn protocol.Connection, cm *protocol.ClusterConfig) {
    deviceID := conn.DeviceID()
    
    // 1. 解析对方宣布的文件夹
    for _, folder := range cm.Folders {
        // 检查是否共享
        fcfg, ok := m.cfg.Folder(folder.ID)
        if !ok {
            continue // 没有这个文件夹
        }
        
        // 2. 比较索引序列号
        localSeq, _ := m.sdb.GetDeviceSequence(folder.ID, protocol.LocalDeviceID)
        remoteSeq := folder.Device.Sequence
        
        if remoteSeq > localSeq {
            // 对方有更新，需要拉取
            m.needPull(folder.ID, deviceID)
        }
    }
    
    // 3. 发送自己的索引
    m.sendIndexUpdates(conn)
}
```

### 2. 自动接受文件夹

**代码位置**: `lib/model/model.go` - `handleAutoAccepts()`

```go
func (m *model) handleAutoAccepts(deviceID protocol.DeviceID, 
                                   folder protocol.Folder, 
                                   from config.FolderConfiguration, 
                                   ok bool, 
                                   defaults config.FolderConfiguration) (config.FolderConfiguration, bool) {
    // 当设备启用了 AutoAcceptFolders
    // 自动创建并共享新文件夹
    
    fcfg := from.Copy()
    fcfg.ID = folder.ID
    fcfg.Label = folder.Label
    fcfg.Path = defaults.Path  // 使用默认路径
    fcfg.Devices = append(fcfg.Devices, config.FolderDeviceConfiguration{
        DeviceID: deviceID,
    })
    
    return fcfg, true
}
```

### 3. Introducer 机制（高级）

Introducer 允许一个设备自动将其他设备介绍给你：

```xml
<device id="DEVICE_C" introducer="true">
  <!-- C 是 introducer -->
  <!-- C 介绍的设备和文件夹会自动添加 -->
</device>
```

**代码实现**:
```go
func (m *model) introduceDevice(device protocol.Device, 
                                 introducerCfg config.DeviceConfiguration) config.DeviceConfiguration {
    // 自动添加 introducer 介绍的设备
    newDevice := config.DeviceConfiguration{
        DeviceID:   device.ID,
        IntroducedBy: introducerCfg.DeviceID,  // 记录是由谁介绍的
    }
    
    return newDevice
}
```

### 4. 数据库持久化保证

```
设备 C 的 SQLite 数据库:

local_files 表:
├─ 记录 C 自己的文件
└─ sequence 单调递增

remote_files 表:
├─ from_A: A 的文件索引
│  ├─ file: document.txt
│  ├─ sequence: 103
│  └─ version: {A:12}
│
└─ from_B: B 的文件索引
   ├─ file: document.txt
   ├─ sequence: 95
   └─ version: {A:11, B:5}

global_files 表:
├─ 综合所有设备的最新状态
├─ document.txt → 最新版本 {A:12}
└─ needs_sync 标记

关键: 即使 A 和 B 都离线
      C 的数据库也保存了完整的索引
      任一设备上线都能同步
```

## 实际应用场景

### 场景 1: 家庭文件同步

```
需求:
├─ 办公室电脑同步到家里
├─ 手机备份照片
├─ 家庭共享媒体库
└─ 不需要同时在线

方案:
└─ 家庭 NAS 作为中转

配置:
├─ NAS 24/7 运行
├─ 办公室电脑 → NAS（上班时间）
├─ 家里电脑 → NAS（晚上）

优势:
✅ 数据留在本地，隐私好

```

```
         C (云服务器)
        /    |    \
  北京      纽约    伦敦
   A        B       D

配置:
├─ 云服务器选在中间位置（如新加坡）
├─ 所有成员连接到 C
├─ 启用压缩节省带宽
├─ 设置合理的速率限制
└─ 使用版本控制防止误删

同步流程:
A (北京 10:00) 修改文件
  ↓
C (新加坡 10:00) 同步
  ↓
B (纽约 21:00 前一天) 上线同步
  ↓
D (伦敦 03:00) 上线同步

结果: 所有成员获得最新文件
      无需同时在线
```

### 场景 3: 数据备份

```
需求:
├─ 重要数据多地点备份
├─ 防止单点故障
└─ 自动同步

方案:
└─ 多个中转设备（冗余）

架构:
    A (办公室)
   / \
  C1  C2
  |   |
  B1  B2
 (家) (家2)

配置:
├─ C1 和 C2 都作为中转
├─ A 同时同步到 C1 和 C2
├─ B1 从 C1 同步
├─ B2 从 C2 同步
└─ 任一 C 故障，另一个可用

优势:
✅ 高可用性
✅ 地理分散
✅ 数据冗余
```

### 2. 网络优化

```xml
<options>
  <!-- 增加并发连接 -->
  <maxConcurrentIncoming>20</maxConcurrentIncoming>
  
  <!-- 调整速率限制 -->
  <maxSendKbps>0</maxSendKbps>  <!-- 0 = 无限制 -->

  <compression>metadata</compression>

<device id="DEVICE_ID">
  <!-- 多连接提高可靠性 -->
  <numConnections>3</numConnections>
</device>
```

### 3. 文件夹优化

```xml
<folder id="default">
  <!-- 文件监控（实时检测变更） -->
  <fsWatcherEnabled>true</fsWatcherEnabled>
  <fsWatcherDelayS>10</fsWatcherDelayS>
  
  <!-- 定期扫描（兜底） -->
  <rescanIntervalS>3600</rescanIntervalS>
  
  <!-- 忽略小文件变更（减少扫描） -->
  <ignorePerms>false</ignorePerms>
  
  <!-- 最大并发写入 -->
  <maxConcurrentWrites>16</maxConcurrentWrites>
</folder>
```

### 4. 存储优化

```bash
# 使用 SSD 提高数据库性能

syncthing debug reset-database
```

## 故障排查

### 问题 1: 设备无法发现

**症状**: A 和 C 显示 "Disconnected"

**排查步骤**:

```bash
# 1. 检查设备 ID 是否正确
# 在设备 C 上:
curl -s http://127.0.0.1:8384/rest/system/config | jq '.devices[] | {name, deviceID}'

# 2. 检查发现服务
curl -s http://127.0.0.1:8384/rest/system/discovered | jq

# 3. 查看日志
journalctl --user -u syncthing -f
# 或
tail -f ~/.local/state/syncthing/syncthing.log

# 4. 测试网络连接
nc -zv C_IP 22000
```

**解决方案**:
- ✅ 确认设备 ID 正确
- ✅ 检查防火墙规则
- ✅ 启用全局发现
- ✅ 尝试手动指定地址

### 问题 2: 同步速度慢

**排查**:

```bash
# 1. 检查速率限制
curl -s http://127.0.0.1:8384/rest/system/config | jq '.options | {maxSendKbps, maxRecvKbps}'

# 2. 查看连接状态
curl -s http://127.0.0.1:8384/rest/system/connections | jq

# 3. 检查是否在直连还是中继
# GUI 中查看设备详情
# "直连" vs "通过中继"
```

**优化**:
```xml
<!-- 解除速率限制 -->
<options>
  <maxSendKbps>0</maxSendKbps>
  <maxRecvKbps>0</maxRecvKbps>
</options>
```

### 问题 3: 文件夹不同步

**排查**:

```bash
# 1. 检查文件夹状态
curl -s http://127.0.0.1:8384/rest/db/status?folder=default | jq

# 查看 needFiles 数量
{
  "needFiles": 10,  <!-- 需要同步的文件数 -->
  "needBytes": 1234567
}

# 2. 查看忽略的文件
curl -s http://127.0.0.1:8384/rest/db/ignores?folder=default | jq

# 3. 强制重新扫描
curl -X POST http://127.0.0.1:8384/rest/db/scan?folder=default \
  -H "X-Api-Key: YOUR_KEY"
```

## 自动化脚本

### 脚本 1: 批量配置设备

```bash
#!/bin/bash
# add_devices.sh

# 设备列表
DEVICES=(
  "AAAAA-BBBBB-CCCCC-DDDDD-EEEEE-FFFFF-GGGGG-HHHHH:办公室电脑"
  "11111-22222-33333-44444-55555-66666-77777-88888:家里电脑"
)

API_KEY="YOUR_API_KEY"
API_URL="http://127.0.0.1:8384"

for device in "${DEVICES[@]}"; do
  IFS=':' read -r id name <<< "$device"
  
  echo "添加设备: $name ($id)"
  
  curl -X PUT "$API_URL/rest/system/config/device" \
    -H "X-Api-Key: $API_KEY" \
    -H "Content-Type: application/json" \
    -d "{
      \"deviceID\": \"$id\",
      \"name\": \"$name\",
      \"addresses\": [\"dynamic\"],
      \"autoAcceptFolders\": true,
      \"compression\": \"metadata\"
    }"
  
  echo ""
done

echo "所有设备添加完成！"
```

### 脚本 2: 监控同步状态

```bash
#!/bin/bash
# monitor_sync.sh

API_KEY="YOUR_API_KEY"
API_URL="http://127.0.0.1:8384"

while true; do
  clear
  echo "=== Syncthing 同步状态监控 ==="
  echo "时间: $(date)"
  echo ""
  
  # 获取文件夹状态
  echo "--- 文件夹状态 ---"
  curl -s "$API_URL/rest/db/status?folder=default" \
    -H "X-Api-Key: $API_KEY" | jq '{
    globalFiles: .globalFiles,
    globalBytes: (.globalBytes / 1024 / 1024 | round),
    needFiles: .needFiles,
    needBytes: (.needBytes / 1024 / 1024 | round)
  }'
  
  echo ""
  echo "--- 设备连接状态 ---"
  curl -s "$API_URL/rest/system/connections" \
    -H "X-Api-Key: $API_KEY" | jq '.[] | {
    device: .deviceID,
    connected: .connected,
    type: .type
  }'
  
  sleep 10
done
```

### 脚本 3: 自动备份配置

```bash
#!/bin/bash
# backup_config.sh

API_KEY="YOUR_API_KEY"
API_URL="http://127.0.0.1:8384"
BACKUP_DIR="/path/to/backups"
DATE=$(date +%Y%m%d_%H%M%S)

mkdir -p $BACKUP_DIR

# 备份配置
curl -s "$API_URL/rest/system/config" \
  -H "X-Api-Key: $API_KEY" > \
  "$BACKUP_DIR/config_$DATE.json"

# 备份数据库统计
curl -s "$API_URL/rest/debug/db" \
  -H "X-Api-Key: $API_KEY" > \
  "$BACKUP_DIR/db_stats_$DATE.json"

# 清理 30 天前的备份
find $BACKUP_DIR -name "*.json" -mtime +30 -delete

echo "配置已备份到 $BACKUP_DIR"
```

### 中转设备方案的核心优势

```
┌────────────────────────────────────────┐
│          中转设备方案优势                │
├────────────────────────────────────────┤
│                                        │
│  ✅ 不需要同时在线                      │
│     A 和 B 可以完全不重叠               │
│                                        │
│  ✅ 数据持久化                          │
│     C 保存完整的文件和索引               │
│                                        │
│  ✅ 自动同步                            │
│     任一设备上线立即同步                 │
│                                        │
│  ✅ 端到端加密                          │
│     即使是公网云服务器也安全              │
│                                        │
│  ✅ 灵活部署                            │
│     NAS/云服务器/树莓派都可以             │
│                                        │
│  ✅ 成本低                             │
│     树莓派 ~470 元一次性投入              │
│     云服务器 ~50-100 元/月              │
│                                        │
│  ✅ 高可靠性                            │
│     数据库 WAL 模式保证数据不丢失          │
│                                        │
└────────────────────────────────────────┘
```
