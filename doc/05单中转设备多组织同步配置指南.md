# 📄 Syncthing 单中转设备多组织同步配置指南

> **目标**：使用一台 Syncthing 中转设备（C），同时为 `财务部` 和 `研发部` 两个独立组织提供文件同步服务，各组织数据完全隔离。

---

## 🧰 一、前期准备

### 1. 确认中转设备环境
确保您的中转设备（C）已满足以下条件：
*   ✅ 已安装 Syncthing（v1.27+，推荐最新版）
*   ✅ 已开机并能持续运行（7x24）
*   ✅ 磁盘空间充足（例如：`/var/syncthing` 目录有 1TB 可用空间）
*   ✅ 网络通畅（能被 `FIN-A`, `FIN-B`, `DEV-A`, `DEV-B` 设备访问）

### 2. 获取所有设备 ID
在每台需要同步的设备上，打开 Syncthing Web UI（`http://设备IP:8384`），进入 **`设置 → 常规 → 设备 ID`**，复制并记录以下 ID：
*   `FIN-A_DEVICE_ID`：财务部电脑 A 的设备 ID（如 `AAAAA-BBBBB-CCCCC-DDDDD-EEEEE-FFFFF-GGGGG-HHHHH`）
*   `FIN-B_DEVICE_ID`：财务部服务器 B 的设备 ID
*   `DEV-A_DEVICE_ID`：研发部电脑 A 的设备 ID
*   `DEV-B_DEVICE_ID`：研发部服务器 B 的设备 ID
*   `C_DEVICE_ID`：**中转设备 C 自己的设备 ID**（这是关键！必须记录）

> 💡 **提示**：设备 ID 是一长串由 `-` 分隔的字母数字组合，务必**一字不差**地复制。

---

## ⚙️ 二、在中转设备 C 上配置多组织

### 步骤 1：停止 Syncthing 服务（安全操作）
```bash
# 如果是 systemd 服务（Linux 云服务器/NAS）
sudo systemctl stop syncthing@root

# 如果是 Docker 容器
docker stop syncthing

# 如果是手动运行（Windows/macOS）
# 关闭 Syncthing 应用程序或终端进程
```

### 步骤 2：备份原始配置（强烈建议！）
```bash
# Linux/macOS
cp ~/.config/syncthing/config.xml ~/.config/syncthing/config.xml.backup_$(date +%Y%m%d)

# Windows (PowerShell)
Copy-Item "$env:LOCALAPPDATA\Syncthing\config.xml" "$env:LOCALAPPDATA\Syncthing\config.xml.backup_$(Get-Date -Format 'yyyyMMdd')"
```

### 步骤 3：编辑 `config.xml` 文件
使用文本编辑器（如 `nano`, `vim`, VS Code）打开中转设备 C 的配置文件：
*   **Linux/macOS**: `~/.config/syncthing/config.xml`
*   **Windows**: `%LOCALAPPDATA%\Syncthing\config.xml`

**将 `<configuration>` 标签内的内容，** **完全替换为以下配置**：

```xml
<configuration version="52">
  <!-- ========== 组织 1：财务部 ========= -->
  <folder id="finance" label="财务部文件" 
          path="/var/syncthing/finance" 
          type="sendreceive"
          rescanIntervalS="3600"
          fsWatcherEnabled="true"
          ignorePerms="false"
          autoNormalize="true">
    <device id="FIN-A_DEVICE_ID"/>
    <device id="FIN-B_DEVICE_ID"/>
    <device id="C_DEVICE_ID"/>
    
    <!-- 财务部版本控制：保留1年历史 -->
    <versioning type="staggered">
      <param key="maxAge" val="31536000"/>
      <param key="cleanInterval" val="3600"/>
    </versioning>
  </folder>

  <!-- ========== 组织 2：研发部 ========= -->
  <folder id="development" label="研发部代码" 
          path="/var/syncthing/development" 
          type="sendreceive"
          rescanIntervalS="1800"
          fsWatcherEnabled="true"
          ignorePerms="false"
          autoNormalize="true">
    <device id="DEV-A_DEVICE_ID"/>
    <device id="DEV-B_DEVICE_ID"/>
    <device id="C_DEVICE_ID"/>
    
    <!-- 研发部版本控制：保留7天历史（更频繁的变更） -->
    <versioning type="staggered">
      <param key="maxAge" val="604800"/>
      <param key="cleanInterval" val="1800"/>
    </versioning>
  </folder>

  <!-- ========== 共享设备定义 ========= -->
  <device id="FIN-A_DEVICE_ID" name="财务-A" compression="metadata">
    <address>dynamic</address>
    <autoAcceptFolders>true</autoAcceptFolders>
  </device>
  <device id="FIN-B_DEVICE_ID" name="财务-B" compression="metadata">
    <address>dynamic</address>
    <autoAcceptFolders>true</autoAcceptFolders>
  </device>
  <device id="DEV-A_DEVICE_ID" name="研发-A" compression="metadata">
    <address>dynamic</address>
    <autoAcceptFolders>true</autoAcceptFolders>
  </device>
  <device id="DEV-B_DEVICE_ID" name="研发-B" compression="metadata">
    <address>dynamic</address>
    <autoAcceptFolders>true</autoAcceptFolders>
  </device>
  <device id="C_DEVICE_ID" name="中转设备-C" compression="metadata">
    <address>dynamic</address>
  </device>

  <!-- ========== 全局选项 ========= -->
  <options>
    <listenAddress><string>default</string></listenAddress>
    <globalAnnounceEnabled>true</globalAnnounceEnabled>
    <localAnnounceEnabled>true</localAnnounceEnabled>
    <relaysEnabled>true</relaysEnabled>
    <maxSendKbps>0</maxSendKbps>
    <maxRecvKbps>0</maxRecvKbps>
    <maxConcurrentIncoming>20</maxConcurrentIncoming>
    <dbEnableAutoClose>false</dbEnableAutoClose>
  </options>
</configuration>
```

### 🔑 步骤 4：替换占位符（最关键一步！）
请**立即**在上面的 XML 配置中，执行以下替换：
*   将 `FIN-A_DEVICE_ID` 替换为您第一步记录的真实 `FIN-A` 设备 ID。
*   将 `FIN-B_DEVICE_ID` 替换为您第一步记录的真实 `FIN-B` 设备 ID。
*   将 `DEV-A_DEVICE_ID` 替换为您第一步记录的真实 `DEV-A` 设备 ID。
*   将 `DEV-B_DEVICE_ID` 替换为您第一步记录的真实 `DEV-B` 设备 ID。
*   将 `C_DEVICE_ID` 替换为您第一步记录的真实 `C` 设备 ID。

> ✅ **检查点**：确保所有 `id="..."` 中的内容都已被替换成真实的、一长串的设备 ID。**一个字符都不能错！**

### 步骤 5：创建文件夹目录并赋权

| 平台 | 操作 |
| :--- | :--- |
| **Linux** | ```bash<br># 创建物理存储目录<br>sudo mkdir -p /var/syncthing/finance /var/syncthing/development<br><br># 赋予 Syncthing 进程读写权限（以 root 用户为例）<br>sudo chown -R root:root /var/syncthing<br>sudo chmod -R 755 /var/syncthing<br>``` |
| **Windows** | 1. 手动在资源管理器中创建两个文件夹：<br>　　`C:\Syncthing\finance`<br>　　`C:\Syncthing\development`<br>2. 确保运行 Syncthing 的用户（通常是当前登录用户）对该文件夹有**完全控制权限**（右键文件夹 → 属性 → 安全 → 编辑 → 添加用户 → 勾选“完全控制”）。 |
| **macOS** | ```bash<br># 在终端中执行<br>mkdir -p ~/Syncthing/finance ~/Syncthing/development<br>``` |

### 步骤 6：启动 Syncthing 服务

| 平台 | 操作 |
| :--- | :--- |
| **Linux (systemd)** | ```bash<br>sudo systemctl start syncthing@root<br>``` |
| **Docker** | ```bash<br>docker start syncthing<br>``` |
| **Windows** | 1. 双击桌面或开始菜单中的 `Syncthing` 图标启动。<br>2. 或者，在 PowerShell 中运行：<br>　　```powershell<br>　　Start-Process "C:\Program Files\Syncthing\Syncthing.exe"<br>　　``` |
| **macOS** | 1. 双击 `.dmg` 安装包中的 `Syncthing.app` 启动。<br>2. 或者，在终端中运行：<br>　　```bash<br>　　open -a Syncthing<br>　　``` |

### 🌐 步骤 7：更新 `config.xml` 中的路径（关键！）

在 `config.xml` 的 `<folder>` 配置中，`path` 属性必须使用**对应平台的绝对路径格式**：<br><br>*   **Linux**: `/var/syncthing/finance`<br>*   **Windows**: `C:\Syncthing\finance` 或 `C:/Syncthing/finance`<br>*   **macOS**: `/Users/YourUsername/Syncthing/finance`<br><br>> 🔍 **验证方法**：启动 Syncthing 后，在 Web UI 的 **`设置 → 常规 → 配置文件`** 中，点击 `config.xml` 旁边的 `编辑` 按钮，它会自动打开系统默认的文本编辑器，并显示当前生效的、已解析为绝对路径的配置。您可以直接在此处确认路径是否正确。

### 📌 跨平台注意事项

*   **防火墙**：Windows/macOS 自带防火墙可能会阻止 Syncthing 的端口（22000 TCP/UDP, 21027 UDP）。首次启动时，系统通常会弹出提示，**请务必允许**。<br><br>*   **开机自启**：<br>　　- **Windows**：Syncthing 安装程序会提供“开机启动”选项，勾选即可。<br>　　- **macOS**：在 Syncthing Web UI 的 **`设置 → 常规 → 启动时运行`** 中启用。<br><br>*   **性能考量**：对于高负载场景（如数百个设备、TB 级数据），Linux 服务器通常比桌面版 Windows/macOS 更稳定、资源占用更低，但这属于“推荐”而非“必须”。<br><br>*   **路径格式**：在 `config.xml` 中，Windows 用户请使用双反斜杠 `\\` 或正斜杠 `/`；macOS/Linux 用户请使用正斜杠 `/`。Syncthing 会自动处理兼容性问题。<br><br>---

## 🌐 三、在各组织设备上添加中转设备

### 在 `FIN-A`、`FIN-B`、`DEV-A`、`DEV-B` 上操作：
1.  打开设备上的 Syncthing Web UI（`http://本机IP:8384`）。
2.  点击右上角 **`+ 添加远程设备`**。
3.  在弹出的窗口中：
    *   **设备 ID**：粘贴您记录的 `C_DEVICE_ID`（中转设备 C 的 ID）。
    *   **设备名称**：填写 `中转设备-C`。
    *   **地址**：填写 `C_IP:22000`（例如 `192.168.1.100:22000`，即中转设备 C 的内网 IP 和默认端口）。
4.  点击 **`保存`**。
5.  **重要**：此时，中转设备 C 会向您发送一个“共享文件夹”的请求。请在 Web UI 的 **`通知`** 区域找到该请求，并点击 **`接受`**。

> 💡 **原理**：当您在 `FIN-A` 上添加了 `C_DEVICE_ID` 后，C 会自动发现 `FIN-A` 并尝试与之共享 `finance` 文件夹。`FIN-A` 接受后，同步即建立。

## ✅ 四、验证与测试

1.  **检查状态**：在中转设备 C 的 Web UI (`http://C_IP:8384`) 中，您应该能看到：
    *   `FIN-A`, `FIN-B`, `DEV-A`, `DEV-B` 四个设备的状态均为 **`在线`**。
    *   在 `finance` 文件夹详情页，看到 `FIN-A` 和 `FIN-B` 的同步状态为 **`已同步`**。
    *   在 `development` 文件夹详情页，看到 `DEV-A` 和 `DEV-B` 的同步状态为 **`已同步`**。

2.  **功能测试**：
    *   在 `FIN-A` 的 `/var/syncthing/finance` 目录（或您配置的对应路径）下，新建一个文件 `test_finance.txt`。
    *   等待 1-2 分钟，检查 `FIN-B` 和 `C` 的对应目录下是否出现了该文件。
    *   在 `DEV-A` 的 `/var/syncthing/development` 目录下，新建一个文件 `test_dev.txt`。
    *   等待 1-2 分钟，检查 `DEV-B` 和 `C` 的对应目录下是否出现了该文件。
    *   **✅ 成功标志**：`test_finance.txt` **只出现在 `finance` 目录**，`test_dev.txt` **只出现在 `development` 目录**，两者绝不交叉。

## 📌 五、后续管理与扩展

*   **添加新组织**：只需在 `config.xml` 中复制一个 `<folder>` 块，修改 `id`、`label`、`path` 和 `<device>` 列表，然后重启服务即可。
*   **调整策略**：如需为某个组织关闭实时监控，将 `<fsWatcherEnabled>true</fsWatcherEnabled>` 改为 `false`，并确保 `<rescanIntervalS>` 设置合理。
*   **查看日志**：如果遇到问题，在 Web UI 的 **`操作 → 日志`** 中可以实时查看详细信息。
